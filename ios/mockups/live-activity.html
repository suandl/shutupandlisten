Lock screen & Dynamic Island — the session survives the pocket

The defining scenario is a locked phone on a table, or in a pocket on a walk. With background audio keeping the pipeline alive (W1a), the Live Activity is the only UI most of a session will ever show: elapsed time, one coarse state, a turn count — and, at most once in a while, the fact that a question is waiting. It never shows streaming words on the lock screen.

ActivityKit update budget — the contract

Elapsed timeText(timerInterval:pauseTime:) — system-rendered, zero updates consumed. Never tick the clock yourself.
State transitions onlyActivity.update() fires solely on: session start · a thought landing (turn count, coalesced) · question arrival · question answered/resumed · session end. Locally delivered (the audio background mode keeps the process alive), so no push token, no remote updates, no APNs.
Never per-pausePauses are seconds-scale; animating the arc fill on the lock screen would burn the budget and be throttled. The mini ring shows state, not progress. The in-app hero owns the live arc.
End of sessionactivity.end(dismissalPolicy: .after(30s)) with a final state showing the question the session left with — a last quiet artifact, then gone.
New targetRequires a widget-extension target (ActivityAttributes shared with the app), and the “End” pill is a LiveActivityIntent. See README for sizing.
  • Minimal is just the breathing empty ring — recognizable at 22 pt because it's the only mark the brand has.
  • Compact carries exactly two facts: alive (ring) and how long (mono elapsed). Question state swaps the ring for the ember point — the same one-symbol grammar taught by the session screen.
  • Expanded adds the turn count and the only remote control worth having: End. No transcript, no question text in the island — it's a status surface, not a reading surface.
